# Changelog

## Unreleased

- Phase C4/C5 complete: fetched a full year (8,760h, no gaps) of real 2023 ERA5 wind for the configured North Sea site; computed the model's real annual capacity factor (0.397, inside the published 0.23-0.52 range) against a peer-reviewed reference (`docs/validation.md`); ran and committed three real annual dispatch runs (`configs/annual.yaml`, `outputs/annual_2023/`) — the wind-only and grid-only-cumulative variants are genuinely infeasible against real demand/wind (not a bug, see `docs/reproducibility.md`), and the recorded successful run (grid+storage, hourly demand) still leaves ~16% of annual demand unmet, a real capacity-planning finding surfaced only by running at annual scale against real data.
- Added an ENTSO-E day-ahead price ingestion path (`data/entsoe.py`), same discipline as ERA5: fail-loud coverage checking, cached raw file, committed provenance record. Deferred during Phase A per REVAMP_PLAN.md's own fallback; built anyway while waiting on the ERA5 annual fetch, using the same "build and unit-test hermetically before real credentials exist" approach that worked for ERA5. Caught and fixed a real bug: reusing ERA5's UTC-day coverage check for ENTSO-E's local-market-day fetches silently mishandled timezone offsets — see `docs/data_provenance.md`. No live fetch has been run (needs a separate `ENTSOE_API_KEY`) and it is not yet wired into `pynexus solve`.
- Wired Phase A/B (storage/grid/heat) into `pynexus solve`/`verify` (`--enable-storage`, `--enable-grid`, `--enable-heat`), which were previously reachable only via direct Python calls to `ElectrolyzerDispatchOptimizer.optimize()`. Extended `optimization/verification.py`'s independent recomputation to be storage/grid/heat-aware (it previously always checked `p <= wind`, which is wrong once grid import exists) — verified against the locked 168h reference objective (unchanged) and a new combined-features integration test suite (`tests/test_dispatch_integration.py`).
- Added electrolyser waste-heat recovery, heat storage, and a backup boiler to the dispatch model (`optimize(enable_heat=True, heat_demand_mw=...)`), opt-in and off by default. The coupled cost objective now values delivered hydrogen and heat, not just penalising shortfall — see `docs/formulation.md`.
- Found and documented a real, tested result: at the current `DEMAND_PENALTY` (1000 EUR/kg), the coupled objective's hydrogen/heat value terms have zero measurable effect on electrolyser dispatch — that penalty structurally dominates any plausible value signal. Confirmed by isolating the mechanism (lowering the penalty makes the coupling immediately effective) and by a figure. See `docs/results.md`.
- Rewrote the README opening and `pyproject.toml` description to headline the multi-vector (electricity/hydrogen/heat) scope, per REVAMP_PLAN.md Phase B5.
- Added hydrogen storage (`s`/`h_in`/`h_out`, terminal condition) and grid import/export (`g_imp`/`g_exp`/`curtail`) to the dispatch model, both opt-in via `optimize(enable_storage=True, enable_grid=True)` and off by default — the pre-Phase-A model and its locked reference objective values are unchanged. See `docs/formulation.md`.
- Added hydrogen mass-balance data reconciliation (`optimization/reconciliation.py`): single-constraint WLS + chi-square(1) gross-error test, same method already used in this portfolio's ThermoTwin repository. Deliberately does not attempt per-sensor fault localization — see `docs/reconciliation.md` for why that would be a false-precision claim with only one redundant constraint.
- Added `pynexus fetch-era5-year` (monthly-chunked annual ERA5 fetch — a single year-long request is rejected by CDS as too large) and `pynexus solve --wind-csv` (real ERA5 wind paired with the existing synthetic price/carbon generator, explicitly labeled as a hybrid input source).
- Fixed two bugs found by running the ERA5 ingestion path against the live CDS API: the time coordinate is `valid_time` not `time` on the unified CDS API, and calendar-coverage checking must use UTC day boundaries, not the configured local timezone (a genuinely complete UTC day was being reported as incomplete). See `docs/data_provenance.md`.
- Ran a live ERA5 validation fetch (North Sea site, 2 days) successfully against the Copernicus CDS API.
- Added a real ERA5 ingestion path (`data/era5.py`, `pynexus fetch-era5`): CDS request construction, nearest-grid-cell extraction, 100m-to-hub-height shear correction (power-law/log-law), fail-loud calendar-gap checking, and a committed provenance record schema (`data/provenance.py`).
- Added a pluggable turbine power curve (`wind_turbine.power_curve_model: "tabulated"`) alongside the existing cubic default, and promoted wake/electrical-loss/availability factors to named, sourced, config-driven parameters.
- Corrected timestep scaling for cumulative demand, ramps and shortfall penalties.
- Added known-optimum/failure tests and explicit optimal-termination gating.
- Added a non-interactive CLI, run manifests and independent CSV verification.

- Added package metadata, CI, community files, and explicit MIT licensing.
- Documented the implemented formulation, provenance boundary, assumptions, and verification status.
- Added deterministic component and dispatch tests plus a tiny configuration.
- Qualified unimplemented live-data and annual-run claims.
